# Timeline

Интерактивная вертикальная шкала времени: React 19 + TypeScript, Konva/react-konva для рендера, Zustand для состояния, Vite для сборки.

## Как вести работу

- Задача сформулирована неточно, противоречиво или в ней есть непонятное — сначала уточнить у автора, что именно он хочет, и только потом писать код.
- Не писать кучу кода, если возможно: выбирать решение с наименьшим объёмом нового кода и данных, не заводить второй источник истины.
- Держать архитектурную чистоту: не сваливать десятки файлов в одну директорию, раскладывать по одному понятному паттерну на каждую часть проекта. Не усложнять раньше времени.
- Инструменты — маленькие переиспользуемые куски с вызовом в одну строку, а не одноразовые скрипты на сотни строк. Логи и промежуточные выгрузки в проекте не хранить. Перед тем как писать новый, свериться с индексом `tools/README.md`; туда же строку про новый.
- Задачу крупнее пары правок начинать с плана. Если план крупный — собрать под него команду ролей, не только инженерных: архитектор, инженер, аналитик, дизайнер — те, что относятся к предмету задачи.
- Задачи проекта ведутся в трекере (реквизиты — у оператора, в репозитории их нет). Перед работой найти задачу и взять её, по ходу двигать по доске, в конце закрыть с результатом; задачи нет — работать можно, но сказать об этом.

## Раскладка

- `src/timeline/` — компоненты канвы: `Timeline`, `TimeScale`, `TimeDivision`, `CoordinateAxes`. Наружу через `src/timeline/index.ts` отдаются только `Timeline` и `TimeDivision`: остальные читают стор объемлющего `Timeline` и сами по себе не рендерятся.
- `src/services/` — чистая логика без React и без состояния: таблица ступеней масштаба и форматирование подписей (`timeScale`), перевод времени в координату (`screenGeometry`), drag (`dragController` — фабрика на экземпляр, состояние в переданном сторе).
- `src/hooks/` — связка стора и чистых функций (`useTimeScale`, `useTimeY`). Арифметика живёт в `services`, хуки — тонкие обёртки, чтобы её можно было тестировать без рендера.
- `src/stores/` — состояние вида (`createTimelineStore` + контекст в `timelineStoreContext`). Стор создаётся на каждый экземпляр `Timeline`, глобальных синглтонов в проекте нет. Тип называется `TimelineViewportState` намеренно: это про то, куда смотрит камера. Документ (события, дорожки, ветвление линий) сюда класть нельзя — два вида одного таймлайна обязаны показывать одни и те же события.
- `src/constants/timeScaleConstants.ts` — константы отрисовки делений. Сама таблица интервалов от секунд до тысячелетий — в `services/timeScale.ts` и передаётся в стор параметром: это контракт шкалы, правки меняют поведение зума на всех уровнях.
- `src/pages/` — страницы роутера.

## Проверка

- `npm run lint && npm run build` — обязательный прогон перед тем, как отдавать результат.
- `npm run dev` — превью на http://localhost:5173; визуальные правки шкалы проверять глазами на нескольких уровнях зума (секунды, дни, годы, тысячелетия), а не только на дефолтном.
- Автотестов в проекте нет. Появятся — вписать команду в `.harness/project-profile.yaml` (`commands.targeted_test`).

## Харнесс

Параметры проекта — в `.harness/project-profile.yaml`, читать его перед использованием глобальных харнесс-навыков. Файл локальный, в репозиторий не коммитится. Установленные копии навыков в пользовательских директориях не править.

## Публичность

Репозиторий публичный. Не добавлять в него внутренние ссылки, адреса инфраструктуры, локальные пути рабочей машины и любые реквизиты доступа — ни в код, ни в документацию, ни в коммит-сообщения.
